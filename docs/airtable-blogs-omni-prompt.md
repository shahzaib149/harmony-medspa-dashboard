# Airtable Omni prompt: create the Harmony Blogs table

> Current base status (verified August 7, 2026): a correctly structured `Blogs` table already exists with table ID `tbltyc852o1xnmyEi`, and the five launch articles are already present as Draft records. Do **not** run this prompt in that base unless the table is intentionally being rebuilt in a different base.

Paste the prompt below into Airtable Omni while you are inside the same base used by the Harmony Leads and Nurture tables.

```text
Create one new table named exactly "Blogs" in this existing base. Do not modify, rename, delete, link, or migrate any existing table or record.

Create these fields in this exact order, with these exact names and types:

1. Title — Single line text. Make this the primary field.
2. Slug — Single line text.
3. Status — Single select with exactly two choices: Draft and Published. Use Draft as the default when possible.
4. Primary Keyword — Single line text.
5. Category — Single line text.
6. Created At — Date with time enabled; use the ISO-friendly local date/time format when available.
7. Updated At — Date with time enabled; use the ISO-friendly local date/time format when available.
8. Published At — Date with time enabled; allow this field to remain empty for drafts.
9. Created By — Single line text.
10. Updated By — Single line text.
11. CMS Data — Long text. Do not convert this to rich text, an AI field, an attachment, or a linked-record field. It will store JSON generated by the Harmony dashboard.

Create these views:

- All Articles — Grid view; no filter; sort Updated At descending.
- Drafts — Grid view filtered where Status is Draft; sort Updated At descending.
- Published — Grid view filtered where Status is Published; sort Published At descending.

Do not add automations that publish articles, change Status, rewrite CMS Data, or generate content. Publishing must remain a manual action in the Harmony dashboard.

After creating the table, show me a final checklist containing the table name, every field name and type, both Status choices, and all three view names. Do not create sample records.
```

## After Omni finishes

1. Open the table and confirm `Title` is the primary field.
2. Confirm `CMS Data` is Long text.
3. Copy the table ID from the Airtable URL or API documentation.
4. Set `AIRTABLE_BLOGS_TABLE_ID` in both Vercel projects.
5. Set the same `AIRTABLE_BLOGS_BASE_ID` and Airtable token in both projects.
6. In the dashboard, open **Blogs** and click **Import launch drafts**. The importer is idempotent by slug and will skip matching records.
